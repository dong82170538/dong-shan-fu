# 当前离线里程碑的协调层决策

以下是负责人为独立实现选定的保守技术策略，不是原软件行为，也不是用户已确认的具体经营策略。

- 使用 Python 3.12 标准库、SQLite WAL、`synchronous=FULL`。商品、SKU、项目状态、结果和成功事件在同一事务提交；成功计数从持久记录计算。
- 崩溃或工作进程退出时，运行任务标为 `interrupted`；已提交结果保留，旧在途项回到 pending 并增加代际。只能经明确 `resume` 恢复。尚未开始的 queued 任务可在引擎重启后继续；paused 不自动恢复。
- 暂停和取消通过事务更新状态并增加 item generation。每次结果提交在同一写事务重新校验任务运行态和 item generation。迟到结果只记录固定事件，不写商品或成功。
- 仅 fixture 的本地、可证明幂等操作支持有限重试：默认手动最多 3 次；可明确选择 automatic_fixture 模式，验收使用最多 2 次、500ms 退避。上限包含暂停和崩溃后的物理重做，最后预算耗尽保留输入并标 attempt_budget_exhausted。已成功项不重跑；鉴权失效取消自动重试，不重试未知外部发布。
- 幂等键只承诺本数据库的任务唯一性。用户键内部位于 `manual/` 命名空间，调度键位于 `schedule/`，防止交叉冲突。同键不同规范化参数返回冲突。
- 物理计算线程数不超过 1..8 的配置上限。超时只使逻辑结果失败；不合作的旧计算仍占用物理槽位直到返回，旧结果作废。当前 fixture 最长延时 5 秒；未来真实适配器需要可中止 I/O 或隔离进程。
- 一次性 UTC 与每日 IANA 时区调度均已实现。引擎启动时错过的计划记录为 missed 并跳过；运行时超过 2 秒容差也跳过。每日 occurrence 以 schedule_id+UTC due 唯一落库，两个重启不重复留痕。未来 DST 歧义/不存在时段不擅自选边，转 needs_attention；已过去的歧义候选跳过后可求下一有效日。
- `mock_fee_v1` 用虚构费用输入演示消息交接的公式；桌面和扩展划线基数分别为换汇后费用与计算售价。另有自有 `cost_plus_v1`，单独版本、公式和基数。费用模型和汇率均不是原厂后端或真实经营建议。
- CNY/RUB/USD 使用显式方向、十进制字符串与币种标签。不将 YN、未知符号或 EUR 的旧歧义静默纳入自有合同。不跨币种汇总金额。
- 所有真实店铺连接、鉴权和发布能力关闭。新增本地 fixture 会话代际守卫：401/402 使账号失效、取消该账号任务和定时器；旧 code0 不恢复会话，提交/恢复/重试/claim/提交结果均检查守卫。fake-login 明确为 fixture，绝不是真实登录；退出只确认本地状态，远端退出为 unconfirmed。无真实凭据存储、原厂服务调用、平台采集或上架。桌面与扩展仍保留为目标表面，而不是改成淘宝工具。

- SQLite schema v1→v2 迁移在写事务持有后读取版本，并保证键转换幂等；并发打开旧库不会重复改写键或丢任务。
- 请求期限与商品期限独立。请求 poll/cancel/callback 经 RLock 串行，终态不可复活；前置 observer 阻塞也不能越过硬期限。
- 扩展 SKU 校验通过自有核心/实际本地 HTTP API 验证。自写 MV3 源已准备，实际宿主加载失败且官方测试浏览器下载被 CDN403 阻止；保持未验证，不换域名下载或放宽扩展权限。
